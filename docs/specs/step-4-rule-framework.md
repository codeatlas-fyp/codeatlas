## Purpose

Give every contradiction case one shape (a pure `Rule`), and turn their results into one verdict
by a fixed truth table, so a verdict never depends on scores, weights or rule order.

## Inputs and outputs

| Item | Signature |
|---|---|
| `evaluate.rules.base.Rule` (Protocol) | `case: CaseId`, `version: str`, `required_evidence: tuple[str, ...]`, `check(bundle: EvidenceBundle, links: list[TraceLink], policy: Policy) -> CheckResult` |
| `evaluate.rules.default_rules()` | `-> tuple[Rule, ...]`; empty until step 7 |
| `evaluate.rules.ruleset_version(rules)` | `-> str`, e.g. `"C1@1,C3@1"`; `"none"` when empty |
| `evaluate.verdict.decide(results)` | `list[CheckResult] -> VerdictValue` (truth table) |
| `evaluate.verdict.run_rules(rules, bundle, links)` | `-> list[CheckResult]`, sorted by case |
| `pipeline.evaluate_bundle(bundle, bundle_hash, rules=None)` | `-> Verdict` with `verdict_hash` |

**Decision (layering).** §6 says `evaluate.verdict` computes the verdict hash, but §4 contract
K1 lets `evaluate` import only `schema`, and the hash needs `bundle.hashing`. So `evaluate.verdict`
decides the value, and `pipeline.evaluate_bundle` (application layer, §8 `pipeline.py`) seals
it with the hash. This function is also the evaluator injected into `bundle.replay`.

## Truth table (§7.4), first match wins

| Order | Condition | Verdict |
|---|---|---|
| 1 | any result VIOLATED with severity `block` | FAIL |
| 2 | any result VIOLATED with severity `review` | REVIEW |
| 3 | any `required` result INSUFFICIENT_EVIDENCE | UNKNOWN |
| 4 | otherwise (includes no results, SATISFIED, NOT_APPLICABLE, VIOLATED with severity `none`) | PASS |

## Rule contract

- Each rule is pure: no I/O, no clock, no randomness (§15). Time comes from the bundle.
- `check` must return a `CheckResult` whose `case` equals the rule's `case`; otherwise
  `run_rules` raises `ValueError`.
- Two rules with the same case are an error (`ValueError`).
- `required_evidence` names `EvidenceBundle` fields the rule reads (§15 declaration).
- A rule that raises is a bug: `pipeline.evaluate_bundle` lets the exception surface as
  `EvidenceValidationError` (exit 4) and no verdict is produced ("never partial", §15).

## Acceptance criteria

- **AC1** Every row of the truth table has a test, including the first-match order (a `block`
  violation beats a `review` violation, which beats a required INSUFFICIENT_EVIDENCE).
- **AC2** INSUFFICIENT_EVIDENCE on a result with `required=False` does not make UNKNOWN.
- **AC3 (property)** For any list of rules, every permutation gives the same verdict value,
  results and `verdict_hash`.
- **AC4** A rule returning another case, or two rules with the same case, raise `ValueError`.
- **AC5** A rule that raises makes `evaluate_bundle` raise `EvidenceValidationError` (exit 4).
- **AC6** `ruleset_version` is independent of rule order and changes when any rule version
  changes.
- **AC7** `evaluate_bundle` is the evaluator for `bundle.replay`: the G1 sample bundle, stored
  with its verdict, replays with `match=True`.
- **AC8** `Rule` protocol: a class with `case`, `version`, `required_evidence` and `check` passes
  `mypy`; `required_evidence` of every default rule names real `EvidenceBundle` fields.

## Decisions made while implementing

- `run_rules` wraps an exception from a rule as `RuntimeError("rule <case> failed: ...")`, and
  `evaluate_bundle` turns any evaluation error into `EvidenceValidationError` (exit 4), so the
  failing case is named and no verdict is produced.
- `run_rules` passes `bundle.policy` as the `policy` argument: the policy is frozen inside the
  bundle (step 2, S3), so replay never reads a live policy file.
- Sample verdict: `PASS`, `ruleset_version` `none`, `verdict_hash`
  `8a04ba3de298471d9b4c9a7686dc88de78f2db44260934b1cf27e19a29afd15f`. It must be regenerated with
  `scripts/make_sample_bundle.py` when step 7 adds rules.
